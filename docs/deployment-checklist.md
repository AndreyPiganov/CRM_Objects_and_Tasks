# Чек-лист публикации

## Supabase

- [ ] Повторить локальные проверки из `docs/local-validation.md` на актуальной ветке.
- [ ] Создать бесплатный проект и сохранить reference ID.
- [ ] Отключить открытую Email-регистрацию.
- [ ] Применить обе миграции командой `supabase db push`.
- [ ] Создать `manager@example.com`, `worker1@example.com`, `worker2@example.com` с подтверждёнными email.
- [ ] Выполнить `supabase/seed.example.sql`.
- [ ] Выполнить `supabase/tests/database/rls_and_workflow.sql` и получить 28 успешных проверок.
- [ ] Убедиться, что в браузер передаётся только anon/publishable key, не `service_role`.

## Vercel

- [ ] Импортировать GitHub-репозиторий.
- [ ] Выбрать Vite либо задать `npm run build` и output directory `dist`.
- [ ] Добавить `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` для Production и Preview.
- [ ] Выполнить deployment и проверить прямое открытие `/objects` и `/tasks/:id`.

## Приёмка под ролями

- [ ] Постановщик видит все три объекта и задачи в разных статусах.
- [ ] Постановщик создаёт/редактирует/удаляет объект и задачу.
- [ ] Постановщик принимает задачу и не может вернуть её без комментария.
- [ ] Первый исполнитель видит только свои задачи и объекты.
- [ ] Второй исполнитель не видит задачи первого даже по прямой ссылке.
- [ ] Исполнители выполняют только разрешённые переходы.
- [ ] После каждого перехода в истории верно отображаются пользователь, время и статусы.
- [ ] После мягкого удаления запись исчезает из UI, а история остаётся в базе.

## Передача

- [ ] Передать ссылку Vercel и три логина/пароля отдельным сообщением.
- [ ] Убедиться, что GitHub-репозиторий доступен проверяющим.
- [ ] Приложить `docs/manager-overview.md` и `docs/decisions.md`.
