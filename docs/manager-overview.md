# Как работает и защищена CRM

В системе есть две роли. Постановщик видит все стройки и задачи: создаёт их, назначает исполнителя, редактирует данные, принимает результат или возвращает работу с обязательным пояснением. Исполнитель видит только задачи, назначенные лично ему, и только те объекты, где такие задачи есть. Он может взять задачу в работу, отправить её на проверку и повторно начать работу после возврата.

У каждой задачи есть строго заданный путь. Новая задача переходит в работу, затем на проверку. После проверки постановщик либо принимает результат, либо возвращает задачу на доработку. Перепрыгнуть через этап, принять собственную работу или изменить уже принятую задачу по статусу невозможно.

Главная защита находится не в кнопках сайта, а непосредственно в базе данных. Интерфейс скрывает недоступные действия для удобства, но база всё равно заново проверяет пользователя при каждом запросе. Поэтому исполнитель не сможет увидеть чужую задачу или подменить её статус даже через инструменты разработчика либо прямой запрос к Supabase.

Каждое создание и изменение статуса записывается в отдельную историю: кто выполнил действие, когда, из какого статуса и в какой. При возврате также сохраняется комментарий. Приложению разрешено только читать историю — переписать или удалить её через API нельзя.

Удаление сделано безопасным: объект или задача исчезают из рабочих списков, но физически остаются в базе вместе с историей. Это сохраняет след действий для возможной проверки. Самостоятельная регистрация отключена; новых сотрудников и их роли создаёт администратор.
